# Open work after waves 1–3

Date: 2026-09-19 · Status: not started · Crate: filesystem-mcp-rs

Everything here is known, reproducible and written down at the moment it was found, so that none of
it depends on remembering. Waves 1–3 (state directory, per-process logging, tool-call statistics)
are done and pushed; these are the loose ends they exposed or left.

Ordered by what a user would notice first, not by effort.

## 1. CI is red on Linux and macOS, and has been since before wave 1

**What.** `cargo test` fails two integration tests on non-Windows runners:

- `run_command_spawn_failure_includes_operator_hint` (`tests/integration.rs:200`)
- `symlink_escape_allowed_when_flag_set` (`tests/integration.rs:1304`)

**Since when.** Both tests date from the initial commit (`83fcc77`). CI has been failing on those
two runners for at least twelve consecutive runs; the run on `21d67cb`, the commit *before* wave 1,
failed the same way. Until 2026-09-19 the failure was masked: three clippy errors in non-Windows
code aborted the job before the tests ever ran, so nobody saw what was underneath.

**Why it went unseen.** Every local gate in waves 1–3 ran on Windows, where both tests pass. A
matrix that varies the feature set says nothing about the OS axis.

**What is needed.** Read both tests against Unix behaviour: a spawn failure's message differs from
Windows', and symlink escape semantics differ where the flag is honoured. Either the assertion or
the behaviour is wrong; which one is a question for someone who can run them. **This cannot be
verified from a Windows machine** - CI is the only feedback loop, so expect a few push-and-watch
cycles. Effort: M.

## 3. The seam split stopped at Windows

`InputDrv` / `WinDrv` / `ScreenDrv` / `ClipDrv` were split by audience (queries vs actions,
reading a window vs driving it) and the gates now follow the consumers. Only the win32 backend
implements any of them. `x11`, `wayland` and `mac` are named in
`tools/computer/driver/CLAUDE.md` and do not exist.

Nothing is broken by this - a missing domain answers `unsupported` loudly - but the split was
done with one implementor, so the trait boundaries are a hypothesis about the second one. Revisit
when a Unix backend starts, and expect `ScreenDrv` to be the one that moves: `cursor_pos` and
`color_at` are GDI on Windows and would be XTEST/Quartz elsewhere. Effort: L, and not now.

## 4. Statistics: what the counters deliberately do not say

Not defects; written down because each looks like one to a reader who meets it cold.

- **A call that panics leaves no row.** The seam records after the dispatch returns and a panic
  unwinds past it, so a panicking tool appears only as a crash report under `<state>/panics`.
  Counting them would mean wrapping every dispatch in `catch_unwind`.
- **`totals.calls` can lead the sum of the rows** under HTTP, by however many calls are in flight:
  the atomic is bumped before the lock is taken.
- **`err_params` means "no such tool"**, not "bad arguments" - rmcp turns a deserialisation failure
  into `is_error`, which lands in `err_flagged`.
- **A `SIGKILL` loses the counters entirely.** That is the price of having no flush machinery, and
  it was chosen deliberately after the first design (SQLite + flush task + lease + compaction) was
  scrapped.

## 5. Documentation that is now a record rather than a description

The three wave plans and the design spec under `docs/superpowers/` carry superseded banners and
keep their bodies. Do not edit the bodies to match the code: a plan rewritten after the fact stops
being evidence of what was decided and why.

`.superpowers/` is untracked (gitignored) and is the subagent ledger - task briefs, reports and
review packages. It is a record of the work, not documentation of the product, and nothing there
needs to be kept in step.
